The workshop shows a procedural placeholder coupé. Its shapes are rough, and a
livery judged on it says little about how the livery reads on a real car. The

Product conclusions, confirmed by the owner:

  closed coupé of about 650 000 triangles. The placeholder no longer appears in the
  workshop or in rendered images.
- Real size (about 4.52 m long, 1.30 m high), standing on the ground, nose the same
  way as before. The paint stays silver; only the body paint takes the livery —
  glass, wheels, lights, black plastic and chrome never do.
- Interior, badge and number plate stay as the model has them; doors and wheels
  do not move. The model is credited in `README.md` under `素材`.
- The guide images under the five artboards are regenerated from the 911. The two
  designs, `calibration` and `stripes`, are unchanged and land on the 911 at the
  same millimetre positions, even where `stripes` no longer follows its contours.
- The first frame waits for the car to load. If it cannot load, the page says it
  cannot start rendering and why.
- Everything else (switching, lighting, address, live updates) is unchanged.
- Not in this plan: choosing a car in the page, opening doors, changing the paint
  colour, removing the badge or plate, keeping the placeholder as an option.

### Decisions & tradeoffs

- **D1 The model reaches the workshop through a one-time import into the workshop's
  own compact file, `models/porsche-911.car`, about 4 to 6 MB.** The import reads a
  plain (Draco-decoded) GLB and writes only what the renderer uses: per part its
  surface class, tint, positions and normals, and triangles. Rejected: committing
  the decoded GLB (17 MB, of which 2.4 MB textures and a 177 000-triangle clear-coat
  shell the renderer does not use) and parsing glTF at every page load; rejected: a
  Draco decoder at run time (a dependency in browser and Node for a file that never
  changes). The Draco decode itself is one external command,
  `npx -y @gltf-transform/cli@4 copy <draco.glb> <plain.glb>`, run before importing.
  Based on: the source file's inspection (Draco-compressed, 45 meshes, 14
  materials) and a single 17 MB push being at the edge of what this network
  carries.
- **D2 Which material becomes which surface class is a table in the import, and an
  unknown material stops the import.** The table was established from a prototype
  render through the workshop's own scene. `coat` (a transparent clear-coat shell
  over the paint) and `Material` (a 2-triangle shadow plane) are dropped.
- **D3 The import scales the model uniformly so that its overall length is
  4.519 m** (the 992 Carrera 4S), turns it into the car frame (source +Z is the
  nose, +Y up; car x = source z, car y = source y, car z = −source x) and places it
  with the wheels on y = 0 and the origin under the centre of its length and width.
  The source file's own scale makes it 3 % short.
- **D4 The placeholder and its mesh toolkit are deleted;** the projection check and
  the guides use the 911. The projection is model-independent, but the check exists
  to prove it on the car the owner looks at.
- **D5 The model has no seam polylines;** its panel gaps are modelled. The contract
  keeps `seams` (empty here) and the scene skips the seam draw when there are none.
- **D6 The car loads before the scene is created, in the browser and in Node, from
  the same decoder.** A failure stops the renderer like any other start-up failure.
- **D7 The model is CC BY-SA 4.0.** The converted file is a derivative and is
  distributed under the same licence; `README.md` says so next to the credit. The
  repository's code stays MIT.

### Goal

This repository is a WebGPU previewer (the `vgpu` library, Vite, TypeScript; the app
is at the repository root: `index.html`, `src/`, `scripts/`). It shows a car wearing
a livery. Every car reaches the renderer through one contract, `CarModel` in
`src/car/model.ts` (parts with a surface class, optional tint, positions, normals and
triangle indices, in the car frame: metres, +X nose, +Y up, +Z the car's right,
origin on the ground under the centre, wheels touching y = 0). Today
`src/car/index.ts` returns a procedural placeholder. After this work it returns a
Porsche 911 imported from a GLB into a compact file of this repository's own.

### Milestone 1: The import and the file

#### T1 · One module defines the `.car` file, both ways

- Where: new `src/car/format.ts` (shared).
- After:
  - `encodeCar(model: CarModel): Uint8Array` and `decodeCar(bytes: Uint8Array): CarModel`.
    `decodeCar(encodeCar(m))` gives back every part's name, surface and tint
    exactly, positions within 0.1 mm, normals within 0.5°, and the same triangles.
  - Layout, little-endian: the 4 bytes `LCAR`, a `uint32` format version (1), a
    `uint32` JSON length, the JSON (UTF-8, padded with spaces to a multiple of 4),
    then the binary data. The JSON holds the model name, the position quantisation
    (an origin and a step per axis), and per part its name, surface, tint (if any)
    and a list of chunks with their vertex and index counts and byte offsets.
  - A part is stored as chunks of at most 65 536 vertices. Per vertex: position as
    3 × `uint16` quantised over the model's bounds; normal as 2 × `int16`
    octahedral. Per chunk: indices as `uint16`, local to the chunk. The encoder
    splits a part into chunks itself (any triangle-preserving split is fine; it may
    duplicate vertices at chunk boundaries). Pad each array to 4 bytes.
  - `decodeCar` returns `Uint32Array` indices offset per chunk, `Float32Array`
    positions and unit normals, `seams: []`, and throws a short `Error` on a wrong
    magic, an unknown version or data ending early.
- Don't: add a dependency.

#### T2 · The import turns a plain GLB into the car file

- Where: new `scripts/import-car.ts`; `package.json` — a script
  `"import-car": "node scripts/import-car.ts"`.
- Change: Read a GLB given as the first argument (path relative to where the
  command is run, like `render --out`), walk the default scene's node hierarchy
  applying each node's matrix or TRS (normals with the inverse-transpose), group
  primitives by material, map them through the table below, transform into the car
  frame (D3), and write `models/porsche-911.car` with `encodeCar`. Print a one-line
  summary per part (name, class, triangles) and the final bounds.
- After:
  - Accepts only uncompressed GLB (glTF 2.0, binary): a file that lists
    `KHR_draco_mesh_compression` or `EXT_meshopt_compression` in
    `extensionsRequired` stops with
    `import-car: the file is compressed; decode it first: npx -y @gltf-transform/cli@4 copy <in.glb> <out.glb>`.
    Reads POSITION and NORMAL (FLOAT) and indices (UNSIGNED_BYTE, SHORT or INT, or
    none), triangle primitives only; ignores every other attribute, texture and
    extension.
  - A material not in the table stops the import, naming it.
  - Material table (one part per material, part name = material name):

    | Material       | Class   | Tint (linear RGB)   |
    | -------------- | ------- | ------------------- |
    | `paint`        | paint   | —                   |
    | `window`       | glass   | —                   |
    | `glass`        | light   | 0.80, 0.82, 0.85    |
    | `lights`       | light   | 0.85, 0.87, 0.90    |
    | `plastic`      | trim    | 0.020, 0.020, 0.022 |
    | `full_black`   | trim    | 0.010, 0.010, 0.011 |
    | `tex_shiny`    | trim    | 0.05, 0.05, 0.05    |
    | `Material.001` | trim    | 0.80, 0.25, 0.00    |
    | `logo`         | trim    | 0.60, 0.50, 0.20    |
    | `license`      | trim    | 0.70, 0.70, 0.70    |
    | `silver`       | wheel   | 0.55, 0.55, 0.56    |
    | `rubber`       | wheel   | 0.02, 0.02, 0.02    |
    | `coat`         | dropped |                     |
    | `Material`     | dropped |                     |

  - Car frame (D3): car x = source z, car y = source y, car z = −source x (after
    the scene's own transforms); then a uniform scale so that the x extent of all
    kept parts is 4.519 m; then a translation so that the lowest point of the
    `wheel` parts is at y = 0 and the x and z extents are centred on 0.
  - The model's name in the file is `Porsche 911 Carrera 4S`. The table, the
    length and the axis mapping are plain data at the top of the script, with the
    source's URL, author and licence in a comment, so a different car is a
    different table.
  - The script's header comment documents the whole procedure: download the source
    (`https://raw.githubusercontent.com/playcanvas/web-components/main/examples/assets/models/porsche-911-carrera-4s.glb`),
    decode it with the `npx` command above, run `pnpm import-car <plain.glb>`,
    then `pnpm guides`.
